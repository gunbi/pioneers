# 代码评审

1. 对照任务目标、验收条件和接口契约。使用角色可用的 Git 工具读取实际差异，并检查受影响的调用方。
2. 先检查行为正确性、回归、边界条件和错误处理。再检查接口兼容、状态归属、模块依赖和可维护性。关注实际影响，并控制评审范围。
3. 核对测试是否覆盖关键成功和失败场景。能运行时记录测试命令与结果。条件不足的检查标为未验证。
4. 每条问题写清文件位置、触发条件、影响和证据，区分阻塞问题与改进建议。验收项逐条标记通过、失败或未验证，注明对应证据。跨角色交接时附上变更或报告的可访问引用。
