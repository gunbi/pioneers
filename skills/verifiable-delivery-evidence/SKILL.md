# 交付证据包

[English edition](SKILL.en.md)

1. 开工前明确验收对象、环境或样本、对照基线与通过条件。普通修复用精确的复现步骤和期待行为。多阶段交付逐项核实平台状态、审批、实际部署和流量或数据处理，按任务范围提供证据。
2. 在实际交付的提交、构建或发布批次上验证。记录版本、环境、命令或操作、预期与实际结果，以及未验证范围。变更合入或交付版本变化后，复跑受影响的检查。命令和证据中的凭据应脱敏。
3. 迁移、切流、容量等高风险变更先用代表性样本试验，再用独立路径回读。数据场景按风险核对总量、关键维度、聚合或代表性明细，标明时间窗、工具版本、样本和截断边界。普通修复由 QA 对照交付版本独立复跑相同命令即可；需要防止同源误判时补上第二条验证路径。
4. 遇到反例先保留原口径和实际结果，再排查是否拿错版本、精度、采样、分页或截断，以及是否存在实际缺陷。需要改口径时，记录调整原因，并保留新旧结果。
5. 按验收项交付证据，写明已验证、未验证和遗留问题。工程师提交自测结果，QA 按项目的验收规则复验。涉及跨团队或对外承诺的结论交 LD 汇总，外部操作沿用 Pioneers 的授权流程。
