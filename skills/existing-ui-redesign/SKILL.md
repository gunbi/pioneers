# 既有界面改版

1. 先读旧版审计、已确认的动线和布局，以及项目已有组件、样式和设计约定。列出本次要改的问题、涉及的页面和需要保留的行为。
2. 按用户做决定的顺序调整导航、内容和主操作。优先复用现有组件与布局体系，针对已观察到的问题调整留白、对齐、文字层级和分组。先确认主要信息与操作在窄屏的顺序，再加视觉细节。
3. 在原有技术栈内完成足以解决问题的改动。核对现有路由、表单状态、筛选条件和失败恢复。需要改变已确认的交互、数据契约或项目约定时，先交接影响与设计决定。
4. 在相同数据和视口下复跑关键场景。记录改前问题、改后表现、仍存在的限制及实际验证版本。用截图说明布局变化，用真实交互结果验证行为。
