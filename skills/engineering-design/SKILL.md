# 编程设计

[English edition](SKILL.en.md)

1. 先写清行为契约，包括输入、输出、边界条件和失败反馈。用项目的类型、接口或明确的校验表达调用要求。
2. 区分规则和执行控制。规则描述哪些条件成立以及怎样计算结果，调度负责何时调用、执行顺序和重试策略。把适合独立验证的校验与转换写成确定性的函数。
3. 为状态确定归属。让持有状态的对象或模块维护状态转换和不变量。把文件、网络、存储等副作用集中在清晰的边界。
4. 有相同行为契约和多个实现时，再考虑用接口、组合或委托复用。把日志、计时等观察行为放在调用边界。保持抽象符合项目当前的变化范围。
5. 按风险补充验证。用小范围测试验证规则与边界，在集成测试里验证实际依赖和失败路径。交付可复现命令及结果。
